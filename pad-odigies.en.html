1. Getting started

  1. Install HEXIS_PAD.apk on an Android phone or tablet (allow "install from unknown sources" for the browser/files app).
  2. The first time, you are asked for the licence code (format PAD-XXXX-XXXX-XXXX). Enter it and tap Activate — internet is needed only this once. See Licence.
  3. Open the app → grant Bluetooth, location and camera permission when asked.
  4. Connecting to the receiver and NTRIP the first time: see First connection step by step.
  5. The app opens with a project. Menu → Projects to create, rename or switch projects.
  6. The top bar shows: solution (FIX green, FLOAT orange, SINGLE/DGPS red), sH / sV (m, 1 sigma), satellites, PDOP, correction age, the QC and NTRIP indicators. Tap the bar → detailed GNSS status.
Display themes: ☀ Sun (maximum contrast for sunlight) and NEO dark (low light). Menu → Settings.

First connection step by step: receiver and NTRIP

These steps are done once. After that the app remembers the receiver and the network: you open the app, switch on the receiver, and they connect by themselves.

Before you start, have ready: the receiver charged, the phone with mobile data (4G/5G) on, and your NTRIP subscription details: caster host, port, user and password. These are provided by the permanent station network you subscribe to.

A. Receiver connection via Bluetooth

  1. Switch on the receiver and wait until the Bluetooth indicator lights up.
  2. Pairing in Android: phone Settings → Bluetooth → Pair new device → choose the receiver. Its name is usually the serial number (S/N) from the label under the receiver. If a PIN is requested: 1234 or 0000.
    Faster: the first time, the app shows the "First receiver connection" screen. The "Pair receiver (Bluetooth)" button opens the Bluetooth settings directly. If the receiver has NFC, just touch the phone to it.
  3. Go back to HEXIS PAD. It finds the receiver and connects by itself. If it does not connect: Home → Receiver & RTK → Connect receiver → Bluetooth → choose the receiver → Connect.
  4. The first time, Android asks for the "Nearby devices" permission. Tap Allow.
  5. Check: the top bar shows a SINGLE or DGPS solution (red) and the number of satellites. The receiver is sending a position. RTK comes with NTRIP (step C).

B. Connection via the receiver Wi-Fi (if Bluetooth sends no position)

  1. Home → Receiver & RTK → Connect via receiver Wi-Fi.
  2. Choose the manufacturer and then the receiver from the list.
  3. Android opens the "Searching for devices" dialog. Choose the receiver Wi-Fi network → Connect. The receiver Wi-Fi is used only by the app, while internet for NTRIP continues over mobile data.
  4. From then on, when the receiver is switched on, the Receiver card on the home screen reads "Receiver found · tap to connect". Tap it and it connects. The Android "Searching for devices" dialog opens only when you ask for it, never by itself. If the phone is already connected to the receiver Wi-Fi, the connection is made automatically, without a dialog.

C. NTRIP: RTK corrections from a permanent station network

  1. Home → Receiver & RTK → NTRIP / RTK.
  2. Permanent station network: choose the network of your subscription (e.g. HEPOS (Hellenic Cadastre)). For another network choose "Other network / my own caster" and enter Caster host and Port (usually 2101).
  3. Enter the User and Password of the subscription.
  4. Tap List: it fetches the network mountpoints. Choose the one your network gave you, usually a VRS in MSM format.
  5. Leave "Send GGA (required for VRS / networks)" checked. Also check "Start automatically when the receiver connects", so it starts by itself every time.
  6. 💾 Profile → save the details under a name. If you have two networks or accounts, you switch with one tap.
  7. Tap Start. The NTRIP indicator in the top bar turns green when corrections arrive. Within a few seconds, up to 1–2 minutes with poor sky view, the solution goes from FLOAT (orange) to FIX (green).

D. Checks before work

  • Antenna height: enter the pole height in the Antenna height field at the bottom of the screen. If the receiver has a phase centre offset, it is set once in Connect receiver. A mistake here means an error in all elevations.
  • Coordinate system: Home → Receiver & RTK → Coordinate system → GGRS87 (HEPOS). This applies the official transformation grid for both planimetry and elevations.
  • FIX with small sH / sV in the top bar and a green QC indicator.
  • Measure a known point (e.g. a trig point or a point with known coordinates and elevation) and compare, before surveying or staking out.

Home screen, map and tool column

Home screen (⌂ button in the column): at the top you see the Project and the Receiver, with a green, orange or red dot for FIX, FLOAT or no solution. Below there are six categories, all in the same blue:

  • Survey: start survey, continuous, static, point by laser, inaccessible point, voice commands.
  • Stakeout: points, line, floors/slopes, squaring, grid.
  • Calculations: all COGO, distance/azimuth, area, line intersection, slope, site calibration.
  • Files & projects: import, points, paste, export/email, projects.
  • Receiver & RTK: receiver connection, NTRIP, base/rover, IMU/bubble, laser, coordinate system.
  • Settings: settings, column tools, user guide.

When you tap a category, you see only its options. The first, main one is the large coloured button. With ‹ Back, or the phone back button, you return to the categories. The Map button at top right takes you straight to the map.

Full-screen map: the tool column is collapsed to the left, so the map takes the full width. It opens with a tap or a swipe from the left edge of the screen (blue tab ›), and closes as soon as you choose a tool, tap on the map, or by itself after a few seconds. You add and remove its tools from "Column tools". If you want it always open: Settings → Screen → Tool column → "Always open". At the top you see FIX, H/V, satellites, Age, QC and NTRIP, and below them the coordinates of the position.

2. Receiver connection

  1. Pair the receiver from the Android Bluetooth settings.
  2. Menu → Connect receiver → Bluetooth, choose the device → Connect.
  3. Alternatively: Wi-Fi / TCP (receiver IP and port), Phone GPS (orientation only) or Simulator (training — long-press on the map = "walk there").

Any NMEA 0183 receiver is supported. GGA is required; GST provides the sH/sV accuracies and GSA the PDOP. If the receiver does not send them, enter a command in the "Init command" field or use Base / Rover → Rover commands.

Automatic connection — no setup

  • First time: if there is no receiver, the "First receiver connection" screen appears. Switch on the receiver, tap "Pair receiver" and choose it in the Bluetooth list. If the receiver has NFC, touch the phone to it. Go back and the app finds it and connects by itself.
  • Every time after that: you open the app and switch on the receiver, in any order. The app connects by itself, and if the receiver is still off it retries every few seconds. Then NTRIP also starts by itself, if you have set it up.
  • Receiver that does not send NMEA: the app automatically sends it enable commands. It also reads the position directly from the published protocols of most receivers (Unicore, NovAtel, u-blox, BESTPOS/BESTNAV messages, NAV-PVT). When this happens, the message "Receiver protocol recognised" appears.
  • Receivers with Wi-Fi (Singular XYZ, CHC, South, Stonex, Hi-Target, Emlid): the most stable route is the receiver Wi-Fi. Receiver → "📶 Connect via receiver Wi-Fi" → manufacturer → the receiver from the list. The app joins the receiver Wi-Fi only for itself (mobile data stays for NTRIP), finds the port carrying the position by itself and from then on connects automatically. When the receiver is off, the app silently checks in the background whether its Wi-Fi has appeared and connects by itself as soon as it switches on — without dialogs. On receivers that do not output NMEA from the factory (e.g. Singular X1 Lite), the receiver page opens once so you can enable the TCP NMEA-0183 output (port 9000, GGA+GST+GSA, 1 Hz) — this does not touch Bluetooth or the manufacturer's software. When the receiver is on and nearby, the "Receiver" card reads "Receiver found · tap to connect". The Android "Searching for devices" dialog opens only when you tap.
  • If a receiver sends only an encrypted manufacturer protocol, the NMEA output is enabled once from the receiver Wi-Fi page or from its app. With "🔎 Receiver data sample" you can send whatever the app receives, so that support can be added.
  • 🧪 Bluetooth log of another app: if the receiver sends a position only to the manufacturer's software, in the Connect receiver dialog tap "🧪 Bluetooth log", follow the 4 steps (Developer options → "Bluetooth HCI snoop log", Start, connect with the manufacturer's software, Stop & send) and send us the file. If the counter stays at 0 kB, tap "🔍 Find & send system file": the app finds the Android log file (btsnoop_hci.log) by itself and sends it. Support for the receiver is added once for all users; nothing changes on the receiver or in the other software.
  • "Disconnect" stops automatic reconnection until you tap "Connect" again.

Receiver not in the list? In the Connect receiver dialog tap ⚙ Bluetooth settings → Pair new device, and choose the receiver. Its name is usually the serial number (S/N) from the label under the receiver, e.g. "2124A0176". Go back and the list refreshes by itself. There is also the "↻ Refresh list" button. Likely GNSS receivers are listed first with ★, while speakers, cars and headphones go to the end.

3. NTRIP (permanent station network)

Connects to any NTRIP network: HEPOS, URANUS, CivilPOS, HxGN SmartNet, JGC NET or your own caster. The connection details are provided by the network with the subscription.

  1. Menu → NTRIP / RTK: caster host, port (usually 2101), user, password.
  2. List → fetches the caster mountpoints. Choose the appropriate one (e.g. VRS / MSM).
  3. Keep "Send GGA" enabled (required for VRS) → Start.
  4. The NTRIP indicator turns green when data arrives. Corrections are forwarded to the receiver via Bluetooth. On a network drop it reconnects automatically.

Base station details

Tap the status bar at the top of the screen (FIX, H/V, satellites, Age). The «GNSS status» window first shows the base you are working with at that moment: network (e.g. HxGN SmartNet), mountpoint, station ID, base coordinates in the project system, lat/lon, ellipsoidal height and ECEF, antenna height, base antenna and receiver, distance from the base and Age. The details are read from the correction messages themselves (RTCM 1005/1006, 1033), so they appear a few seconds after NTRIP starts.

On a VRS network (virtual base), the coordinates are those of the virtual base the caster creates near you. On a single station they are the coordinates of the real station.
💾 Profile: save each network/account for quick switching. "Automatic start" = starts by itself when the receiver connects.

4. Base / Rover and base change

Receiver manufacturer

Menu → Base / Rover: choose a brand (CHC, South, Stonex, Hi-Target, ComNav, Singular XYZ, Kolida, Ruide, Tersus, SatLab, FOIF, Emlid, ArduSimple, Septentrio, Leica, GeoMax, Trimble, Spectra, Topcon, Sokkia). The board's command family is suggested; change it if your model uses another.

u-blox (Emlid etc.)Configuration from the manufacturer's panel; HEXIS PAD works as rover, NTRIP, survey, stakeout.

All commands are shown before they are sent — check them against the receiver manual (especially whether the base height is ellipsoidal or orthometric).

New base

  1. ＋ New base → On known point (choose a point) or Autonomous position "here".
  2. Base antenna height, RTCM port, geoid separation N.
  3. Commands to base… → check → Send (with a Bluetooth connection to the base).
  4. Set as active base: every new point is "tied" to this base.

Base shift

If the base was set up on an autonomous/wrong position: open the base from the list → enter "position used" and "true position" → Apply shift. All points of the base are shifted by dX/dY/dZ and this is recorded in their note.

5. Survey

  1. Point name (increments automatically), code (recent codes as buttons), antenna height (pole + phase centre).
  2. Duration: seconds (1, 2, 3, 5, 10, 15, 30 s, 1 or 3 minutes) or epochs; "Other…" for any value. Epoch = one position solution of the receiver (at 1 Hz, 1 epoch ≈ 1 s). All are averaged. FIX only: FLOAT epochs are rejected.
  3. Wait for FIX (Settings, default 10 s): measurement starts only when the solution stays FIX for this many consecutive seconds; the button shows "⏳ FIX 4/10 s".
  4. As soon as the point is stored, the button briefly turns green "✓ name" (with a sound) and then returns, ready for the next measurement.
  5. Sounds (Settings → Sounds, with volume and test): point-stored sound, rising tone when the solution becomes FIX, low tone and vibration when FIX is lost.
  6. ● MEASURE → quality control is run (section 6). Tapping again during measurement = cancel.
  7. Line with code: consecutive points with the same code are joined into a line (exported to DXF).
  8. ⌖ Offset: point from distance + azimuth (manual or from laser).
  9. Measuring with a name that already exists → comparison of independent measurements and the option "Save as check".

Continuous survey

Home → ⟳ Continuous survey (or the ⟳ tool in the column). You choose by distance (e.g. every 1 m) or by time (e.g. every 2 s), code, "FIX only" and maximum sH. Points are stored automatically as you walk and the names increment by themselves. On the map the bar "⟳ Continuous · N points" appears with the ■ Stop button. If the solution is not FIX or sH exceeds the limit, the bar shows the reason in yellow and no point is stored.

Static

Home → ◷ Static. You enter point, code, antenna height and duration (5 minutes to 2 hours, or "Until I stop it"). The receiver stays still and the app:

  • keeps one solution per second and computes the mean, sH and sV. It uses only FIX solutions when there are any. If there is no FIX at all, the point is marked "NO FIX".
  • logs all receiver data to the file Documents/HEXIS PAD/Static/<project>_<point>_<date>.gnss for post-processing. For office processing the receiver must send raw observations (RTCM3 MSM or the manufacturer's format).
  • at the end shows the result and the "Share / email file" button.

Tapping ◷ again while it runs shows the statistics live and lets you finish earlier.

Drawing a line from point to point

In Survey tap ✎ Draw and in the Draw lines group choose Line (independent straight segments), Polyline (continuous line), Spline (smooth curve through the points) or Polygon (closed polygon). Each button has an icon showing the shape. From then on every point you measure goes into the line — a green bar with the type and number of points appears above the map. You can start from the last measured point. On the bar: ↶ removes the last point from the line (the point remains), ✕ cancels the line (all points remain), ✓ Done completes it. In DXF export the lines come out as LINE / POLYLINE / dense polyline for spline, on layer HP_<code>.

Antenna height = pole + receiver offset

In the Survey field you enter only the pole height. The antenna offset (from the ARP reference point to the phase centre, e.g. 0.068 m for Singular X1 Lite / L1) is added by itself when the receiver has been recognised, or you set it in Settings → "Receiver antenna offset". The field label shows "Pole (+0.068)" and both are recorded in the point properties.

Position error without GST

If the receiver does not send GST (e.g. Singular via Wi-Fi), sH/sV is shown with ~ (estimate from HDOP and solution type: FIX ≈ 1.2 cm × HDOP). In the QC check it counts as a "warning", not a rejection; the actual scatter of the measurement epochs is checked normally.

Inaccessible point within the survey

On the Survey card there is an ✕ Inacc. button, next to Offset. You do not need to leave the survey:

  1. Tap ✕ Inacc. The diagram with the 4 points opens.
  2. Tap "● Measure point 1" (or say "Take"). Then 2, 3, 4. The button moves on to the next by itself.
  3. You see the result, the angle between the lines and a warning if the geometry is weak.
  4. Tap 💾 Save to survey. The point gets the next number of the survey and the current code. It goes into the line (if you are measuring "Line with code") and the numbering continues normally.

With the option "Keep auxiliary points in the list" you decide whether the 4 auxiliary points stay in the list or are deleted. The selector at the top also offers the other methods: distance + azimuth with laser, distance intersection, line extension.

Point with laser rangefinder (DISTO etc.) from 2–3 positions

For points the pole cannot reach: building corner, column, tree, manhole behind a fence. ⟟ Laser button on the Survey card.

  1. Connect the laser in Bluetooth "keyboard mode" (on DISTO: Bluetooth → Keyboard mode) and pair it in Android.
  2. Stand at position 1 and tap "● Position 1: GNSS measurement" (or say "Take").
  3. Rest the laser on the pole, aim at the point and press measure on the laser. The distance is entered in the field by itself. Without a connection, you type it.
  4. Go to position 2, a few metres away, so that the two positions form an angle of 60°–120° with the point. Take a GNSS measurement and a distance again.
  5. There are two possible solutions. Choose Left / Right (looking from position 1 towards 2), or add a 3rd position: the app chooses by itself and shows a residual (RMS) for checking.
  6. 💾 Save to survey: the point gets the next number and your code.

In "Distance correction" you enter e.g. the pole radius, if you measure from the back of the laser resting against the pole. For elevation, choose "Mean Z of positions + dH". The app warns when the geometry is weak or the distances do not "close". The same exists in COGO → Point by laser and in Inaccessible point.

Tilt ↔ strict plumb

With an active IMU, the Survey card has the ∠ Tilt 60° button. If you tap it, it becomes ⊙ Plumb. Tapping the ∠ indicator on the status bar does the same, as do the voice commands "Plumb" / "Tilt".

  • ∠ Tilt: you measure with a tilted pole, up to the receiver limit.
  • ⊙ Plumb: point only with a vertical pole, within the centering tolerance (e.g. ±0.5°). Useful for trig points, control points and bases. If you go outside it, the button reads "⏳ Out of plumb" and waits.
  • Each point records how it was measured and with how much tilt.

IMU — measuring with a tilted pole

If your receiver has an IMU, you measure without levelling. Compensation is done inside the receiver and the app makes sure you do not measure outside the manufacturer's limits.

  • Automatic detection: the app works it out by itself from the data the receiver sends:
    • If the receiver sends a tilt compensation status, the IMU is enabled immediately and the app tells you, also out loud, up to how many degrees are allowed.
    • If it sends only a tilt angle (which may also be a simple electronic bubble), it asks you once whether the receiver has an IMU, and you enter the maximum tilt from its datasheet. If you answer "No", only the centering bubble remains.
    • If the model is known to the app (e.g. Emlid Reach RS3: 60°, CHC i73: 45°), the manufacturer's limit is used. Otherwise 30° is used, until you enter the datasheet limit yourself.
    • Everything can be changed from Menu → IMU / levelling bubble.
  • Indicator: the status bar shows ∠ 12°/60°, green within the limit and red outside it. If it reads ∠ INIT, the IMU needs initialization: rock the pole or walk, as specified by the manufacturer.
  • Protection: above the limit, or before initialization is complete, the measurement does not take a point. The button reads "⏳ Tilt 65° > 60°" and a warning sounds. As soon as you are within the limit, the measurement is taken by itself. The same applies in stakeout, inaccessible point and continuous survey.
  • Digital centering bubble: small, next to the coordinates, so it does not hide the survey area (with the column always open, it is on the "Bubble / IMU" button of the column). The dot shows which way the pole is leaning and the degrees are written next to it. Fluo green = vertical, orange = close, red = outside. With one tap a large bubble appears on the map for precise centering (drag it wherever you like), and another tap hides it. Long-press: bubble / IMU settings. With an IMU, the red dashed circle is the receiver tilt limit.
  • Without IMU (receiver with electronic bubble): the bubble shows the verticality tolerance, e.g. "0.4° · ±0.5°". Green = centred, orange = close, red = outside. With the option "do not take a point outside centering tolerance", the measurement waits until you are centred.
  • The bubble is always shown. When the receiver sends tilt, the bubble uses the receiver and no calibration is needed. Otherwise it uses the phone sensor, marked "phone", if the phone or tablet is mounted on the pole.
  • Phone calibration — automatic, only when needed: if the receiver does not send tilt and the phone has not been calibrated, a message appears by itself: keep the pole tip steady and rock it back-forth and left-right, a few degrees, for about 10″. The bar fills up and the bubble calibrates itself, without a spirit level and without buttons. It is repeated only if you change the phone's position on the mount: tap the bubble when it reads "Calibr.", or from the bubble settings.
  • Your own limit: you can set a lower limit than the manufacturer's, e.g. 30° for higher accuracy.
  • Height: when the receiver gives the position at the pole tip, the pole height is set in the receiver and the app does not subtract it again. This option is on by default.
  • Recording: each point keeps the maximum tilt during the measurement and the receiver model.
  • The app checks the angle when the receiver sends it (PASHR, PSAT HPR, PTNL AVR, HPD messages or Unicore tilt status). If the receiver does not send an angle, it reads "∠ IMU" and you observe the manufacturer's limit yourself.
  • Before work, measure a known point with a tilted pole. This confirms the pole height and the initialization.

Floating measure button

On the map there is a round ● MEASURE button. In stakeout it turns purple and reads RECORD.

  • Tap = measure, exactly like the large button. While measuring it turns orange (■) and green (✓) as soon as the point is stored.
  • Drag = move it wherever suits your hand; it remembers the position. Dragging does not take a measurement.
  • Settings → Floating measure button: "✋ Left-handed" / "Right-handed ✋" moves it to the corresponding side. There is a "Large button" option for gloves, and you can also turn it off.
  • If the Survey or Stakeout card opens beneath it, the button moves up above the card automatically.

Calls and background operation

While a receiver is connected or NTRIP or static is running, the app works with priority, also in the background. If the phone rings, or you open another app, or the screen turns off, nothing stops:

  • The receiver connection, NTRIP corrections, continuous survey and static logging continue normally.
  • The notifications show "HEXIS PAD — Receiver connected · NTRIP". Tapping it returns you to the app. The first time, Android asks for notification permission: tap Allow.
  • During a call the app does not speak (voice confirmation), and the voice command microphone is closed until you return.
  • If Bluetooth is lost during the call, it reconnects by itself, also in the background.
  • The notification disappears when you disconnect the receiver and stop NTRIP.

On some phones (Xiaomi, Huawei, Samsung with "battery saving"), set HEXIS PAD to "Unrestricted" in the Android battery settings.

Voice commands

The 🎙 Voice tool, or Home → Voice commands, or Settings → Voice commands. While it is listening, a green "🎙 Listening…" indicator appears on the map. Tapping it turns it off.

  • "Take" (or "Measure", "Record"): measure a point. In stakeout it records Pn.
  • "Delete": deletes the last measured point. The next number takes its name again.
  • "Undo": restores the deleted point, within 15 s. There is also a yellow "↶ Undo" button on the screen.
  • "Next" / "Previous": stakeout point.
  • "Cancel" / "Stop": stop the measurement or continuous survey.

The app confirms out loud ("Saved P12"). The first time it asks for microphone permission. Recognition is done by the phone's voice service. If you have downloaded the language for offline use (Android Settings → Speech recognition), it also works without internet. The ⌫ Delete last tool does the same as "Delete" with one tap.

6. Continuous RTK quality control (QC)

Based on the NOAA/NGS guidelines for RTK (classes RT1–RT4) and the logic of ISO 17123-8. Every epoch and every measurement is checked.

ClassAccuracy 95% (H/V)PDOPSatssigma (1 sigma)Epochs
RT1 · network / stations2 / 4 cm≤ 2≥ 71 cm180
RT2 · precise topographic4 / 5 cm≤ 3≥ 61.5 cm12
RT3 · topographic / stakeout6 / 8 cm≤ 4≥ 53 cm15
RT4 · rapid survey / GIS20 / 30 cm≤ 6≥ 55 cm10
  • Live: FIX solution, time in FIX, sH/sV, PDOP, satellites, correction age, jump detection (sudden shift in FIX with a stationary pole — possible wrong fix; the FIX timer resets).
  • Per measurement: epoch scatter (std), maximum deviation, worst sH/PDOP, minimum satellites, jumps, non-FIX epochs. Result: OK / WARNING / REJECT — stored with each point and in the CSV.
  • Check measurement on a known point: Points → point → ✓ Check measurement. Comparison against the class tolerance.
Good practice (NGS): check on a known point at the start, in between and at the end; for important points two independent measurements hours apart (RT1/RT2 ~4 hours) with a new solution in between (cover the antenna ~5 s or move >30 m); height check by changing the pole height by 1–2 dm.

7. Stakeout

Point

Target from the list, with ◀ ▶ (next/previous), or ⌖ on the map (points, DXF/DWG vertices). The target circle shows an arrow when you are far away and scaled rings when close. Green = within tolerance, with sound and vibration.

Direction reference: "Reference: movement" (Forward/Back, Right/Left relative to where you walk), "Reference: North" (dX/dY), or "Reference: point" (orientation towards a point, e.g. looking towards a peg). Cut / Fill = design Z − ground.

Line

Drawing polyline (including arcs), two points, or a measured line. Empty chainage = live chainage and perpendicular offset. With chainage + Offset = target; ▶ advances by the "Interval".

Surface (floors, slopes)

From COGO → Floor slope: reference point + main/cross slope %, plane from 3 points, or horizontal. Shows live design Z and Cut/Fill.

Squaring

Baseline A→B: chainage from A and perpendicular offset (+right). Creates the 4 corners of a rectangle with check diagonals.

⛶ full-screen stakeout with large digits. ● RECORD: measures and stores the staked point with the target name and "n" (e.g. P1 → P1n), with dX/dY/dZ from the target, without leaving stakeout; then moves to the next one automatically. 📄 Stakeout confirmation file: CSV and TXT with targets, staked points, deviations and an in/out of tolerance flag — save, share or email. Tolerances: Settings.

Grid from a polygon side (tree planting, piles)

COGO → ⁘ Grid, or the ⁘ tool in the column.

  1. Polygon: a measured line (e.g. the boundary you measured with code BOUNDARY), a closed polyline from the DXF/DWG drawing, or vertices you pick in order.
  2. Base side: the rows run parallel to it (offset). By default it is the longest side and is shown in red on the map.
  3. Spacing: within the row (e.g. 5 m) and between rows (e.g. 5 m). You also set the offset of the 1st row from the base side and the minimum distance from all boundaries.
  4. Pattern: square or diamond (staggered, every second row shifted by half an interval). With the "Center" option each row has equal margins left and right.
  5. The preview is shown live on the map (green points), together with the number of points and rows.
  6. ✓ Create stakeout points: the points are named T1, T2… with code TREE, both of which can be changed. Numbering is serpentine (back and forth), so "Next" always takes you to the adjacent point. Stakeout opens immediately at T1.

Relocalize — shifting points onto known points

For points measured with a false FIX or a wrong base that all came out shifted. Calculations → Relocalize (or the ⇄ tool).

  1. Which points move: all, those measured on a specific day, or from point A to point B. Known and trig points never change.
  2. Known points: "＋ Add known point" → choose the measured point, which has the wrong position. Then enter the true coordinates, either from a known point in the list or by typing them.
  3. 1 known point: shift dX, dY, dZ only. 2: shift and rotation. 3 or more: plus residual check (RMS), and optionally scale.
  4. You see dX, dY, dZ, rotation and residuals, and tap Apply. All points move to the correct position and each point's note records the correction.
  5. ↶ Undo last relocalize: the points return exactly as they were. The last 10 corrections are kept.

9. Coordinate systems

GGRS87 — official HEPOS model (default): the Hellenic Cadastre HTRS07 → GGRS87 transformation (7 parameters + 2 km dE/dN correction grids, bilinear interpolation), built into the app — no file needed. Verified against the official Hellenic Cadastre examples with a deviation below 1 mm. Use it with HEPOS and with networks that provide ETRS89. For Kastellorizo its specific model is applied (3 shifts, TM87 with lon0 = 27°).

"GGRS87 — 3 parameters" (EPSG:2100) is approximate: without the grid the deviation averages ~0.6 m and exceeds 2 m in some areas. Elevations: the Hellenic Cadastre does not yet provide an official geoid with the HEPOS package — orthometric heights come from the receiver model; for centimetre accuracy run a Site calibration on 2–3 known benchmarks.

Other countries: the app picks the system and geoid from your position — see Working abroad. You can also enter your own proj4 definition for any country. Elevations: receiver orthometric or ellipsoidal. For local networks: COGO → Site calibration.

Working abroad

The app works out which country you are in from the receiver position and sets the country's official coordinate system, the national geoid model for heights (where it is freely available) and the country's list of permanent station networks (the local equivalent of HEPOS) in NTRIP.

  • Greece: everything stays as it is — GGRS87 / HEPOS, Hellenic Cadastre and KAEK — whatever language you have chosen. The language never changes the coordinate system or the base maps.
  • Outside Greece: the Hellenic Cadastre and KAEK layers are not shown (neither in the toolbar nor in the base maps).
  • Automatic change only in an empty project. If the project already has points, the app asks once: keep the current system, change, or start a new project in the new country. It never changes the system in the middle of your work.
  • Geoid: downloaded the first time (needs internet) and kept on the device for offline work. Orthometric heights are computed as H = h − N from the receiver's ellipsoidal height. Where there is no national model, heights come from the receiver.
  • Manually: Receiver & RTK → Coordinate system. It shows the working country and the geoid; you can turn off the automatic choice, tap «Apply for my position» or pick another system / your own proj4.

11. Files & email

Import

From email: tap the attachment → "Open with" → HEXIS PAD. The import wizard opens directly. If you have already downloaded it: Import → "Choose file". The dialog opens directly in Downloads.

One "Choose file" button — the type is detected automatically:

  • TXT, CSV, XYZ, PNT, DAT: any separator (comma, semicolon, tab, spaces), decimal comma or point, Greek encoding.
  • XLS, XLSX, ODS: sheet selection.
  • DXF, DWG: drawing basemap, with optional dX/dY shift and import of POINTs as stakeout points.
  • KML, GeoJSON: points in lat, lon → converted to the project system.
  • Paste: text from email, Excel, a message.

Before importing you see a preview: a table with the columns (automatic detection of Name / X / Y / Z / Code — change them if needed), header yes/no, X↔Y swap, lat/lon, a small sketch of the points, a check that they fall in the right area, and handling of duplicate names (rename / skip / replace).

From other apps (Gmail, Files, Drive, Viber): Open with or Share → HEXIS PAD. On a tablet with a browser: drag the file onto the map.

Export

Quick options: Points only (TXT), DXF (points + lines) or All; otherwise you tick the formats one by one. Points are stored internally at full precision; on export, coordinates are written with 4 decimals (0.1 mm) — change to 3 or 5 in Settings → "Coordinate decimals".

TXT, full CSV (accuracies, QC, base, stakeout deviations, photos), DXF (points/names/elevations/codes on layers, lines), KML, GeoJSON, photos — all in a ZIP. 💾 Save (Documents/HEXIS PAD), ↗ Share or ✉ Email (opens the mail app with the files attached).

Base in the TXT: with «+ Base ID on every point» (on by default) every TXT line ends with the ID of the base the point was measured with, e.g. P12,214295.537,4302900.046,62.345,TREE,HxGN_SmartNet/LEFK_RTCM3/2417 (network / mountpoint / station ID). At the end of the file, in lines starting with #, comes the table of bases: ID, network, mountpoint, station ID, base coordinates in the project system, ellipsoidal height, lat/lon, ECEF, antenna height and which points were measured from each base. If the program reading the TXT expects only Name,X,Y,Z,Code, untick the option. The CSV always has the BaseID, BaseX, BaseY columns.

Photos in every export: whichever quick option you choose ("Points only", "DXF", "All"), the point photos always come along. They go into a ZIP file with a photos/ folder, each photo named after its point. The same applies to the stakeout file (CSV + TXT + photos). If you do not want them in a particular send, untick "Point photos".

Battery and power

  • Keep screen on "While working" (default): the screen stays on while the receiver is connected and you have touched it in the last 10 minutes, or while stakeout, continuous survey or static is running. Otherwise it turns off normally, while the receiver connection and NTRIP continue in the background. One touch turns it back on and you are where you were.
  • The map is redrawn only when something visible changes: when you move or the solution changes. When you stand still, processing drops to about 1/4.
  • Power saving: switches on automatically below 30% battery, when not charging. The map and indicators then refresh 2 times per second, and the screen turns off after 3 minutes without a touch, instead of 10.
  • The bubble is never affected: it always stays live.
  • Everything is set in Settings → Power: "Keep screen on" (While working / Always / As set by the phone) and "Power saving" (Automatically / Always / Never).
  • Tip: screen brightness is the biggest drain. In the sun it needs to be high, but in shade or in the evening lower it from the phone.

Licence

  • The code locks to the device where you enter it first. It does not work on another device. If you change phone, ask for a release.
  • Usage-hours licence (e.g. 7 or 10 field hours): only the time the app is open on screen counts — when the screen turns off or you leave the app, counting stops. Warnings at 30′ and 10′ before they run out. The hours are valid until the date shown in "Licence".
  • Trial licence in days: the days count from the moment of activation.
  • With both types the app works normally without internet in the field; usage time is sent when a connection is found. The licence is checked automatically whenever there is internet; if the device goes more than 7 days without any internet (30 for an owner device), it asks for a short check: turn on mobile data and tap Activate.
  • The licence is signed by the server and the app verifies that it is the genuine version. Download HEXIS PAD only from hexis-app.gr/pad.html; modified versions do not open.
  • Settings → Licence: you see the code, how many hours or days remain, how much you have used and the exact expiry. Check now updates it immediately, e.g. after an extension.
  • When it expires or the hours run out, the code screen opens. Your projects and points stay on the device. After the extension, tap Activate again with the same code and continue where you left off.
  • The device time must be correct. If it is set back, the app asks for a check over the internet.
  • Your own devices (owner): on the code screen tap "Owner sign-in with HEXIS-APP account" and enter your hexis-app.gr email and password. The administrator account unlocks the device permanently, without expiry and without hour counting, on as many devices as you like (phone, tablet). The password is not stored on the device.
  • For a code, extension or purchase: 693 322 6314 (call · WhatsApp · Viber).

12. Photos

📷 in Survey (last point), in stakeout (last staked point) or from the point details. Each photo carries a watermark with name, code, coordinates, date and solution, and is exported with the point name.

Where they are stored: each photo stays in the project, linked to its point. It opens from the point details and is exported with Export → Photos (ZIP) / Email. In addition, a copy is saved to the phone automatically, in the folder Documents/HEXIS PAD/Photos/<project>/, named after the point, so it is not lost even if the app is uninstalled. The copy can be turned off in Settings → "Copy every photo to the phone".

Recording in stakeout: when you reach the point, tap ● RECORD. It is measured as a new point, e.g. "3n", with the deviations dX / dY / dZ from the target, and goes into the stakeout file.
